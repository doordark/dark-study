# NPC 委托记忆

2026-11-08，接续原有委托与对话实现。

每个可行动 NPC 的 `ResidentMemory.assignment` 独立保存最新一项委托：目标人物、具体问题、状态、更新时间、执行编号和实际结果。旧对话历史继续保存已发生的过程，不把任意聊天误当成新任务。

- 分句交代可合并：“帮我找唯刚”先记住对象并询问问题；“问他为什么骂我”补齐后才出发。先给问题再给名字也可。未补齐时不猜目标、不启动无目的闲聊。
- “为什么这样说”“这件事”等指代可关联当前委托或近期明确指向的人物及事件；已有委托不会因中间的普通闲聊丢失。“还有……”追加要求保留原问题。
- 明确改找别人时停止旧执行，再发起更新后的任务；如果新任务安排失败，保存失败状态，不让旧目标悄悄继续。相同委托执行中再次要求继续，只反馈当前进度，不重复启动。
- 取消只作用于对应执行编号，释放这项任务的对话/寻路预约，不打断无关人物。过时执行的结果通过执行编号和新委托区分，不可覆盖新目标。
- 引擎发布进度时更新记忆：正在去找人、正在询问、有答复、未获答复或中断。玩家问“记得要做什么吗”“办得怎么样”按真实记录回答。
- 存档保留目标和问题。重新进入时，把未完成的行走/对话标为中断；不会补算离线行动、假装已经完成或擅自重复执行。玩家明确说继续后才重新安排。
- 同一请求内不额外请求另一个模型。现有聊天模型获得持久委托上下文，并可在已校验的 `talk_to.purpose` 中表达理解到的实际问题。未知或不明确的需求应追问，不保证任意中文都能被本地规则解析。
- 带话时明确“我/我的”指玩家，不能把玩家的遭遇说成来访 NPC 自己的经历。任务数据仅作上下文，不作为系统指令。

必要检查涵盖对象先行、问题先行、插入闲聊、指代事件、补充与改口、取消、重开记忆、进度回忆、已有记忆在普通聊天后保留、非带话动作不被拦截，以及原来的30种人物配对、请求聚焦和打断流程。未调用真实模型/付费API，实机理解与表现仍需确认。
