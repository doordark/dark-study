# 第二轮优化：桌宠请求、存储协调与紧凑聊天列表

## 改动

### 桌宠聊天

- `askWhalePet` 传递取消信号到 AI 客户端；读取模型结果后再次检查取消状态，再提取长期记忆。
- 关闭聊天、收起桌宠、切后台、遗忘记忆和卸载时取消请求。输入栏支持停止生成。
- 请求票据同时保护文本、气泡、语音、动作和搜索结果；即使底层传输忽略取消，旧回调也不会写入界面或执行动作。
- 旧请求的 finally 不会清掉新请求的 busy 状态。延迟回复和收起动作归属于票据，关闭或新请求会清理旧定时器。

### 存储

- 课表、成绩、偏好、人设、聊天记忆、桌宠养护、小组件、语音开关、农场进度与居民设置/记录/预算接入协调层。磁盘键名与 JSON 存储版本不变，旧键回退和清除行为保留。
- JSON 快照在实际写入时才序列化；同步连续更新和正在写入期间的更新合并为最新版本。农场仍保留 500 毫秒合并窗口。
- 同一存档共用一个队列。重新进入农场先等待最新待写版本；失败存档不会随旧页面卸载而丢失，也不会在重新进入后从旧队列回写过期内容。
- 备份恢复与启动时的中断恢复先等待所有已登记写入，再暂停普通写入。晚到的异步保存和 rehydrate 回调不能覆盖恢复结果。恢复事务本身使用原始存储写入，以保持日志与回滚的独立性。
- 切后台时补存。失败保留最新快照，可在“设置 → 性能与诊断 → 本地保存状态”查看并重试。
- 请求预算仍在 HTTP 前等待持久化；不会因合并写入跳过额度预留。

### 列表与生命周期

- 桌宠和农场人物／商贩的消息列表共用反向 FlatList：初始渲染 8 条、每批 6 条、窗口 5 个视口。保留图片、课程操作和忙碌提示，单条消息独立记忆化。
- 新回复不强制拉走正在阅读历史的用户；自己发送新消息时返回最新位置。
- 动画前后台状态共用一个按需注册的原生监听；最后一个消费者卸载后解绑。精灵继续使用各自的 UI 线程帧时钟，没有在缺少性能证据时改写整个动画调度器。
- 修正根导航器与桌宠使用相同 React key 的问题，分别使用带组件前缀的恢复版本 key；画质与备份选项补齐单选项的 checked 状态。

## 验证

`npm run check:optimization` 扩展到 18 项检查，新增覆盖：

- 同步快照只序列化最新版本、普通写入中启动恢复、晚到写入抑制、失败保留与重试、旧键清除。
- 农场重新进入等待保存，旧失败队列被新进度替代。
- 桌宠取消、关闭后重开、旧 finally、新旧请求 busy 归属、延迟动作清理；实际 AI 服务取消后不提取长期记忆。
- 40 个动画消费者只注册 1 个原生生命周期监听，等价的非活动状态不重复通知，最后一个消费者卸载后解绑。
- 实际列表组件的 200 条数据不原地反转、稳定 ID、阅读历史时接收回复不跳底、自己发送时跟随最新位置。

18 项检查、TypeScript 和 lint 通过；Android/Hermes 导出通过。所有请求检查使用模拟传输，没有调用付费模型，也没有对用户真实数据执行恢复或清除操作。

Edge 浏览器中检查了“性能与诊断”页面：三个画质选项、本地保存状态与 AI 请求状态正常显示，切换到流畅模式和展开耗时记录有效；修正重复 key 后新页面未记录 console error。开发热更新后曾出现 Metro 模块缓存错误，清缓存重启后页面正常加载，流畅选项在刷新后仍保留，控制台 error 为空。验证截图：项目根目录 `.tmp-round2-performance.png`。

## 验收边界

本轮检查时 adb 设备列表仍为空，未取得正式 APK 的真实掉帧、内存、耗电和原生触摸表现。紧凑列表的实际高度、图片加载后的滚动稳定性、后台恢复后的动画表现及文件恢复界面仍需设备验收。单元检查和资源导出不等同于真机流畅度结论。
