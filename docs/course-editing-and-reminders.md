# 课程局部编辑、作息与提醒

## 修改范围

课程编辑中可以选择「整条重复记录」或「指定周次」。指定周次默认勾选当前浏览周；可同时选择多周。指定周次修改会原子拆分：未选周保留原记录与 id，所选周形成独立记录（若原记录所有周都被选中则保留 id）。其他上课时段不会被同步修改。整条重复记录延续原有规则：时间只修改本条，课程名称、教师、教室等共享信息同步到同一门课程的其他记录。

`updateCourse(id, patch, targetWeeks?)` 是手动编辑、课表助手、大肥鱼和桌宠的共同写入入口。`targetWeeks` 表示修改前的范围；`patch.weeks` 表示修改后的周次，两者不能混用。没有 `targetWeeks` 时修改整条记录。

`Course.startTime/endTime` 为可选精确时间；存在时自动根据当前作息推导节次。手动重新选择节次会清除精确时间，恢复跟随作息。时间表范围之外的时刻会拒绝保存，提示先调整作息。

例如第 8 周周三数据结构从第 1–2 节延长到 08:00–10:40，若该时段覆盖第 1–3 节，则仅第 8 周生成第 1–3 节记录，其余周仍为第 1–2 节。日视图、周视图、正在上课判定、冲突标记、桌面小组件和提醒读取精确时间。

## 作息时间表

设置 → 课表与学期 → 作息时间表，可查看、编辑名称与起止时间、添加或删除末节，并进入原有作息导入流程。保存与导入统一走 `setPeriods`：验证连续编号、合法时间、时间顺序和课程对节次的引用；已有精确时间会重新映射节次。无效修改整次拒绝，不会留下半次更新。异步导入绑定识别时课表，切换课表后需要切回原课表再应用。

持久化沿用项目已有 Zustand / AsyncStorage；没有新增云端服务。课表变化由现有 CourseReminderSync 和 CourseWidgetSync 自动同步。

## 手机系统提醒（Android）

设置 → 提醒与小组件 → 添加到手机闹钟 / 日程，选择未来的一次上课：

- 闹钟：通过 SET_ALARM 打开手机时钟，填入上课前指定分钟的时间与课程名称，由用户保存。Android 标准闹钟接口不支持任意日期，因此仅允许未来 24 小时内的时刻。
- 日程：通过 INSERT 打开系统日历，填入该次上课的实际日期、精确起止时间、教室与教师；在系统日历里选择提醒时间并保存。
- 系统记录是创建时的快照，应用不持有系统记录 id，不能自动更新或撤销。调课后需在系统应用修改。应用内通知独立随课表自动重新排程，关闭应用内通知不会删除系统里保存的记录。
- 系统没有匹配的时钟或日历应用时显示失败提示。闹钟权限在 app.json 中声明，新安装包才会包含该权限。

## 验证

- `node scripts/check-course-editing.cjs`：真实 store 写入与重新水合、局部拆分、精确时刻映射、非法数据原子拒绝、作息校验、小组件和通知时间、通知清理范围、系统 Intent 参数，以及三种助手入口的模拟响应链路。
- `node scripts/check-course-widgets.cjs`
- `node scripts/check-app-iteration.cjs`
- `npx tsc --noEmit`、`npm run lint`、Android Expo export。

模拟响应检查不代表真实模型理解已验证；系统闹钟 / 日历 UI、真机通知声音及厂商后台策略也需要设备验收。
